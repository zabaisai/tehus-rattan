## Decisiones tomadas a partir de la matriz

1. **Una sola fuente para la región**: columnas de `Company`. El JSON no las duplica.
2. **`businessModel` se deriva** de `sellsProducts/sellsServices`; `vertical.businessModel` queda como metadato de origen (plantilla) y no se expone como estado actual.
3. **Un solo motor** (`TenantConfigurationService`): `/configuration` y `/settings` comparten reglas, transacción, bloqueo y auditoría. `CompaniesService` deja de contener lógica de settings.
4. **Sin migración de settings ni backfill**: `storageVersion` refleja lo guardado; v1→v2 solo al editar.
5. **Migración de productos con SQL manual** para que las filas existentes queden `NULL` (tipo efectivo `PRODUCT` en la aplicación) hasta la Fase 5.
6. **Auditoría sin migración**: `AuditLog` ya representa actor, empresa, acción, entidad, fecha y metadatos.
7. **Fuera de alcance** (fases posteriores): navegación dinámica por módulos (Fase 4), backfill de `itemType` (Fase 5), `CompanyLeadSettings` por API, renombres.
